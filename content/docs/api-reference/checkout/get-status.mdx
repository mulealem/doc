# Get session status

<Endpoint method="GET" path="/api/checkout/v1/session/status" auth="Authorization: Bearer" />

Poll this after [submitting a receipt](/api-reference/checkout/submit-receipt). It returns the payment verdict plus the reason a `PENDING` payment is not finished yet.

The same status is what powers payo's hosted pending screen, so the semantics are identical.

## Headers

<Params>
  <Param name="Authorization" type="string" required>
    `Bearer <clientSecret>`
  </Param>
</Params>

## Example

```bash
curl https://dashboard.example.com/api/checkout/v1/session/status \
  -H "authorization: Bearer $CLIENT_SECRET"
```

## Fields

| Field | Meaning |
|---|---|
| `status` | `PENDING`, `APPROVED`, or `REJECTED`. `null` before a receipt is submitted. |
| `stage` | Only while `PENDING`: `VERIFYING` (worker still running), `NEEDS_REVIEW` (a rule denied auto-approval or the verifier failed — a human must look), `FINALIZING` (approved, commit in flight). |
| `code` | Stable machine code — `approved`, `amount_mismatch`, `missing_reference`, `duplicate_reference`, `stale_receipt`, `replay_receipt`, `provider_mismatch`, `receiver_mismatch`, `gate_rejected`, `pending_review`, `verification_failed`, `not_pending`. |
| `reason` | Human-readable detail for `NEEDS_REVIEW`/`REJECTED`. |
| `adminNote` | Note a human reviewer left, when rejected. |

<Callout type="warn">
  Poll every 2–5 seconds and stop as soon as `status` is no longer `PENDING`. Fulfil the order from the `payment.approved` webhook — the poll is a UI convenience, not the source of truth.
</Callout>
