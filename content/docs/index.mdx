# PyGate developer documentation

PyGate is a **receipt-based payment gateway** for merchants and platforms that need to accept payments in markets where card-based processing is unreliable or unavailable. Customers pay via bank transfer or mobile money, photograph the receipt, and upload it. PyGate verifies the receipt against the issuing bank, then notifies you.

This documentation is for developers integrating PyGate into a website, app, or backend. If you only need to sign in and check your dashboard, head to [dashboard.example.com](https://dashboard.example.com).

## How PyGate is different

| | Card gateways | PyGate |
|---|---|---|
| Customer pays with | Card | Bank transfer, mobile money, telebirr, CBE Birr, … |
| You integrate | Card form / iframe | Hosted redirect or a single `POST` |
| Funds settle | 1–3 days, with chargeback risk | Pre-funded — you see the receipt before value moves |
| PCI scope | Yes (SAQ-A at best) | **None** — the page is hosted, no card data ever touches your server |
| Customer friction | 4 fields, OTP, 3DS | Photograph + upload |
| Failure modes | Declines, network errors | OCR misreads (we re-verify with the issuing bank) |
