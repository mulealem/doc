# Admin API

The Admin API is the platform-tier half of the [Projects API](/api-reference/projects/overview). It's designed for marketplace and B2C builders who provision and manage merchant projects programmatically.

## Platform API keys (`pka_…`)

Admin-tier requests authenticate with a **platform API key** sent as a bearer token:

```http
Authorization: Bearer pka_4b1c2d3e4f5g6h7i8j9k0l1m2n3o4p5q6r
```

Platform keys differ from [project API keys](/concepts/api-keys) in three ways:

1. **Scope** — a platform key can create, list, update, and delete *any* project, while a project key is bound to one project.
2. **Storage** — the full key is shown exactly once at creation; only a SHA-256 hash and a 12-character lookup prefix are stored. A lost key cannot be recovered — revoke it and issue a new one.
3. **Lifecycle** — keys are named and individually revocable. Revocation takes effect immediately.

Keys are created and revoked by Payo admins from the dashboard's **Admin → API Keys** page.

## Ownership of created projects

`POST /api/v1/admin/projects` resolves the project owner in this order:

1. `ownerEmail` in the request body, if it matches an existing Payo user.
2. Otherwise, the platform account bound to the API key (set when the key was issued).

This lets a marketplace either map merchants to their existing Payo accounts or keep every merchant project under the platform's own account and hand the merchant only the project `apiKey`.

## Two tiers at a glance

| | Admin (platform) | Project (owner) |
|---|---|---|
| Credential | `pka_…` platform key | `pgk_…` project key |
| Header | `Authorization: Bearer` | `x-api-key` |
| Create projects | ✅ | ❌ |
| List all projects | ✅ | ❌ |
| Manage own project | ✅ (by id) | ✅ |
| Delete project | ✅ | ❌ |

<Callout type="warn">
  Treat platform keys as production secrets. They grant full control of every merchant project on your platform.
</Callout>
