# Hosted checkout page

The hosted checkout page is the surface your customer actually sees. It lives on a separate origin (`checkout.example.com`) from your dashboard and your app, and is fully managed by Payo.

## Flow

```
customer clicks "Pay" on your site
  → you POST /api/v1/orders
  → you receive { paymentUrl, ... }
  → you redirect customer to paymentUrl
  → customer sees hosted page
  → customer picks bank / telebirr
  → customer pays from their bank app
  → customer returns to hosted page
  → customer uploads a screenshot of the receipt
  → hosted page polls for verification
  → on success: returns the customer to your ?returnUrl=
```

## URL

```
https://checkout.example.com/pay/{orderId}
```

The `orderId` is the `orderId` returned by `POST /api/v1/orders`. Don't construct the URL yourself — use the `paymentUrl` field verbatim.

## Customizing the page

By default, the page shows:

- Your project logo (uploaded in the dashboard)
- The order description and amount
- A list of enabled bank accounts the customer can pay into
- A receipt upload widget after the customer pays

You can customize:

- **Logo** — Project → Settings → Logo (PNG, ≤ 500 KB)
- **Accent color** — Project → Settings → Brand
- **Receipt widget language** — localized to English, Amharic, Afaan Oromoo, and Somali
- **Bank account order** — drag to reorder in the dashboard

## Query parameters

You can append optional query parameters to the `paymentUrl`:

| Param | Purpose |
|---|---|
| `?lang=am` | Force UI language (auto-detected from browser by default) |
| `?returnUrl=https://…` | Absolute http/https URL shown as a "Return to merchant" button; the customer is sent there automatically after approval |

## Returning to your site

Pass `?returnUrl=` with an absolute http/https URL. The hosted page renders a **Return to merchant** button and, once the payment is approved, sends the customer back after a short confirmation beat.

The return URL is a convenience, not a reliable event: the customer may close the tab first. Treat fulfilment as webhook-driven:

- Receive the `payment.approved` webhook ([Webhooks](/webhooks/overview)), or
- Poll `GET /api/v1/orders/{orderId}` and check `status === "COMPLETED"`.

<Callout type="warn">
  Never mark an order paid because the customer came back to your success page. Verify with the webhook or the API — otherwise anyone can "complete" an order by editing the URL.
</Callout>
